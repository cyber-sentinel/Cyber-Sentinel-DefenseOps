# Content Model

Each technical artifact should use the following metadata model where relevant.

| Field | Purpose |
|---|---|
| Title | Human-readable use-case name |
| ID | Stable content identifier |
| Status | experimental / test / production-candidate / deprecated |
| Domain | detection / deception / hunt / dfir / ir / automation |
| ATT&CK | Technique/sub-technique mapping |
| Data Sources | Required telemetry |
| Platforms | Windows / Linux / Network / Cloud / Identity / Application |
| Severity | Informational / Low / Medium / High / Critical |
| Confidence | Low / Medium / High |
| Validation | Test procedure and expected result |
| False Positives | Known benign scenarios |
| Production Risk | Performance / availability / operational risks |
| Rollback | Disable or reversal method |
